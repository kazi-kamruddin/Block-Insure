Role-bootstrap receipts must be available before the workers start. Record existing bootstrap receipts rather than replaying them. Application-stage evidence must be supplied from an actual isolated runtime. The runner does not create a browser/worker runtime or generate those bindings from this scenario file.
- Before any later authorized run, confirm one medical reserve (up to 0.012 ETH) and one refund reserve (up to 0.0015 ETH). Reserve 0.002 ETH for fees and retain 0.020 ETH with the admin outside the run budget. The public funding quote requires only role addresses and an HTTPS RPC. ### Public testnet gas rules

The 24 November read-only probes identified Amsterdam on Ethereum Sepolia and Denim on Base Sepolia. Sepolia applied the Amsterdam state-gas schedule, including EIP-8037 code and storage creation, EIP-8038 state access, and EIP-7976 calldata pricing. EIP-7825 bounds Amsterdam execution independently of the 32-bit total transaction gas limit. Base keeps its own execution and fee schedule. Save the canonical fork and block observations with the receipt exports. [Ethereum fork specification](https://eips.ethereum.org/EIPS/eip-7773) · [Ethereum state-gas rules](https://eips.ethereum.org/EIPS/eip-8037) · [Base Denim release](https://github.com/base/base/releases/tag/v1.5.1)

On the sampled Sepolia block below 200 million gas, Tenderly estimated 76,420,286 gas for the current manager initcode and returned the 24,379-byte runtime at the planned 84,067,315 total limit. It returned the same runtime hash as the Base call. The 24,000-byte code-deposit probe cost 37,229,846 estimated gas on Sepolia and 4,896,150 on Base. The manager initcode creates two child contracts, so code-deposit repricing explains most of the roughly 7.05× manager estimate ratio. No deployment change was indicated by these checks. Some provider simulations impose lower caps than the network. Recheck against the intended endpoint on the proposed fresh deployment block.

When supplying a discrepancy evidence file to the comparison, use each operation ID as the key and a record with a reason and evidence reference as its value. Use `explained by protocol pricing` for evidence such as controlled opcode probes and `state difference` for verified prior-state differences. Rows above 5% with missing or unsupported evidence are marked `unexplained`.
